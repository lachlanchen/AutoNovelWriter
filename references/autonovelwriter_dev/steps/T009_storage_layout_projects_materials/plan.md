# T009 Plan: Storage layout (projects) + materials index

## Design Note (Storage + Persist/Derive + Observability)
- Storage fit (standardized runtime layout, configurable but with defaults):
  - Keep current runtime roots:
    - `autonovelwriter/runtime/io/{inbox,outbox}/` (interaction pipe)
    - `autonovelwriter/runtime/state/` (settings + pipeline + runner state)
    - `autonovelwriter/runtime/tasks/` (task queue)
    - `autonovelwriter/runtime/logs/` (logs)
  - Add a projects root under runtime:
    - `autonovelwriter/runtime/projects/<project_id>/`
    - Suggested per-project subfolders (initial pass):
      - `materials/` (user-provided inputs: notes, PDFs, images, research)
      - `interactions/` (chat exports, inbox/outbox snapshots if needed later)
      - `outputs/` (drafts, revisions, exports)
      - `state/` (project-local derived caches: materials index, runner resume pointers for that project)
- Persisted vs derived vs ephemeral:
  - Persisted (disk, gitignored): everything under `autonovelwriter/runtime/` including:
    - `runtime/projects/<project_id>/materials/**` (user drops files here)
    - `runtime/projects/<project_id>/outputs/**`
    - `runtime/state/settings.json` plus a small persisted “active project” pointer (either in settings or a dedicated `runtime/state/active_project.json`).
  - Derived (regenerable): materials index JSON generated by scanning `materials/` (file list, sizes, mtimes, optional sha256 later). Cache can live at `runtime/projects/<project_id>/state/materials_index.json` but must be safe to recompute on demand.
  - Ephemeral (in-memory/UI): current filter/search, selection, expanded folders; localStorage may mirror active project for UX but must not be source of truth.
  - Gitignore: confirm `autonovelwriter/runtime/` remains ignored; do not commit any project content.
- Observability + resumability (API/WS expectations):
  - REST endpoints:
    - `GET /api/projects`: list project IDs + basic metadata (mtime, optional display name).
    - `GET /api/materials/index`: returns `{active_project, projects_root, materials_root, files:[...]}` where files include relative path + type + size + mtime.
    - Optional: `POST /api/projects/active` to set active project (persisted).
  - WS events:
    - Optional but useful: `project_active_changed` and `materials_index_updated`.
    - For acceptance, polling is fine: PWA can re-fetch `/api/materials/index` on an interval; backend can rescan on each request so “drop a file -> appears without restart” is satisfied.

## Acceptance Checklist
- Backend:
  - `GET /api/projects` returns `{ok:true, projects:[...]}` with at least one default project present (e.g. `default`).
  - `GET /api/materials/index` returns active project + file listing for that project’s `materials/`.
  - Dropping a file into `runtime/projects/<active>/materials/` is reflected by subsequent `GET /api/materials/index` without backend restart.
- PWA:
  - Shows active project ID.
  - Shows a read-only list of materials files from the index.
  - Updating the materials folder on disk appears in the UI after the next poll (no reload required).
- Separation:
  - Storage layout is about in-app projects/materials; do not confuse with driver task queue under `references/autonovelwriter_dev/`.
